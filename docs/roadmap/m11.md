# Goal
A project built as vertical slices with layers inside each slice keeps that shape: a slice owns its data and its internals, slices never depend on each other in a circle, and a generated map shows the structure (owner, 2026-10-24: "one slice never directly calls the internal database layer of another slice").

## U86 Data ownership
The owner's rule (2026-10-24): one slice never calls another slice's database layer directly; slices talk through interfaces, events or shared domain services ([Data ownership](../design/data-ownership.md)).
- AC-1 With `architecture.data`, the gate and `check --ci` fail (`ARCH-DATA`) a data edge from outside the owning module, a data node with no owner and not shared, and a node two modules claim; an approved `except` decision covers the edges it lists.
- AC-2 The card lists the data the unit's modules own and the shared data, and how to reach other data.
## U87 Module surfaces and cycles
The owner's go (2026-10-24) on the rest of the vertical-slice-with-layers pattern ([Module surfaces and cycles](../design/module-surface.md)); layers inside a slice use boundaries as they are. The CLI budget goes to 3,700 lines for U86 and U87.
- AC-1 A module with `api` fails `ARCH-API` on an edge from another module to its paths outside `api`; an approved `architecture.api.except` decision covers the edges it lists.
- AC-2 With `architecture.acyclic`, module edges that form a circle fail `ARCH-CYCLE`, once per set of modules; module edges an approved decision lists are left out.
## U88 Codebase map
The owner (2026-10-24): keep a tree in the project's docs that shows the structure of the codebase ([Codebase map](../design/codebase-map.md)).
- AC-1 `aidlc map` writes `<bundle>/codebase-map.md`: the module folders as a tree with each module's data and public paths, top-level folders no module covers, and module dependencies from the graph as a Mermaid flowchart and a table; an unchanged body is not rewritten; `map: false` turns it off.
- AC-2 Merge writes it with the indexes, so the merge commit carries it.
## U89 Plan-wide findings per file
From the first migration (2026-10-24): `aidlc check` on I-3's unit files passed and `next` asked for approval, but I-3's `PLAN-SLICE` showed only in a full check, and failed a later merge.
- AC-1 `check <files>` also reports the findings on the intents of the units among them; `approve` refuses a doc with a `PLAN-DECISION` or `PLAN-SLICE` finding on it or, for a unit, on its intent.
## U90 Codebase map in small pages
From the first migration (2026-10-24): the project's docs check refused the 7,600-char map (4,000 cap, a `**TL;DR:**` line per doc). The CLI budget goes to 3,800 lines.
- AC-1 The map is a tree page and, with a graph, a diagram page and a table page, linked to each other, each opening with a `**TL;DR:**` line; merge writes all three.
## U91 Deploy on the existing platform
From the first migration (2026-10-25): a deploy unit planned its own Argo CD Application, pull secret and names while a sibling infra repo already defined them; the replan came after the unit stopped ([Operations](../design/operations.md)).
- AC-1 With `deploy` in the profile and no `deploy.platform`, plan lint fails each intent that ships (`PLAN-PLATFORM`); `[]` passes.
- AC-2 A standard card lists the `deploy.platform` refs and says to build on them.
## U92 Approved docs within the project's caps
From the first migration (2026-10-25): a unit doc passed at 3,990 chars, its approval stamps took it to 4,019, and the project's own docs check (4,000 cap for every type) failed it; the plugin counted 12,000 for a Unit ([OKF validation](../design/okf-validation.md), [Approvals](../design/approvals.md)).
- AC-1 `docs.caps` sets size caps by type, with `default` for the types it does not name; `check`, the gate and the write hook use them.
- AC-2 `approve` refuses a doc its stamps would take over its cap, naming how much to trim, and writes nothing.
