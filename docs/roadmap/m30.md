# Goal
Every concept the plugin uses has one word at one scale, each word one meaning, and the docs, messages and templates use those words ([Canonical model](../design/canonical-model.md)).

# Bolts
## B254 A complete canonical model
- AC-1 The vocabulary defines every concept the shipped text and the design docs use: the module kinds, the architecture model, the stack pack, the naming registry and the profile; the domain's aggregate, domain model, data node, API contract, integration and domain events, commands, queries, routes and handlers; the test level, acceptance criterion, proof-revert, mutation and scope; the owner's request, requirement, persona, fact, decision, pathway, walking skeleton, method version and the release steps; and the docs bundle, merge gate, review, verdict, focus, agents, worktree, trailer, base, board, retro, stamp and AI model.
- AC-2 A word with several senses is split into one word per sense, and the words to avoid send the bare word, in each sense, to the one it means.
- AC-3 Each scale's words are a page drawn from `cli.json` beside the canonical model, each under its size cap, and a test keeps them in step.
## B255 The risky words in what agents read
- AC-1 The messages, fixes, templates, personas, skill and agents use the words `vocabulary.senses` lists only in an expression that names one sense (architecture model, domain model, AI model; the owner's request, a call; the docs bundle; the API contract; integration event, domain event) or in a code span; the words test reports any other bare use.
## B259 Scale and concurrency
- AC-1 A generated docs bundle of 200 intents and 2,000 bolts runs `status`, `next` and `check` within the time budgets the overview states, each a median of several runs.
- AC-2 Two merges started at once, and a builder's commit during a merge, end with one merge on the base and the other refused or done after it, never a half merge.
- AC-3 Both run in `node --test` at zero AI model tokens: code generates the docs bundle, and the CLI and git play the builders and merges; no agent, AI model or network call, so they run on every CI push.
## B261 An index entry without a description
- AC-1 `check` warns `HOUSE-INDEX-DESC` for each entry the generated indexes would write without a description, naming the index and the entry, so a subfolder of several docs gets its one line written once in the parent index; `aidlc index` keeps that line, and the warning goes.
## B262 Whole-tree checks
- AC-1 `check --tree` runs the path naming rules, the generated ones among them, and the slice checks over every tracked path, as errors in the gate's codes, so a path left from before a rule, such as a brownfield migration's leftover, is reported; without the flag, `check` leaves them to the gate, which counts only a bolt's changes.
## B256 The gate codes split
- AC-1 The generated gate codes page is split by group, each page under its size cap; design docs that contradict each other are reconciled.
## B257 Old forms retired
- AC-1 Once the trial shows no project holds them, the v1 aliases (`units/`, `U-<n>`) are retired, with `upgrade` moving what a project still holds.

B255, B259 and B261 come before the trial runs, B262 from what it showed; B256 and B257 after them, shaped by what they show. The plugin's own code keeps its layout: restructuring tested code for consistency alone adds risk and no gain a user sees.
