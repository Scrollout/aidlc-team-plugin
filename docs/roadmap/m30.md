# Goal
Every concept the plugin uses has one word at one scale, each word one meaning, and the docs, messages and templates use those words ([Canonical model](../design/canonical-model.md)).

# Bolts
## B254 A complete canonical model
- AC-1 The vocabulary defines every concept the shipped text and the design docs use: the module kinds, the architecture model, the stack pack, the naming registry and the profile; the domain's aggregate, domain model, data node, API contract, integration and domain events, commands, queries, routes and handlers; the test level, acceptance criterion, proof-revert, mutation and scope; the owner's request, requirement, persona, fact, decision, pathway, walking skeleton, method version and the release steps; and the docs bundle, merge gate, review, verdict, focus, agents, worktree, trailer, base, board, retro, stamp and AI model.
- AC-2 A word with several senses is split into one word per sense, and the words to avoid send the bare word, in each sense, to the one it means.
- AC-3 Each scale's words are a page drawn from `cli.json` beside the canonical model, each under its size cap, and a test keeps them in step.
## B255 The risky words in what agents read
- AC-1 The messages, fixes, templates, personas, skill and agents use the words `vocabulary.senses` lists only in an expression that names one sense (architecture model, domain model, AI model; the owner's request, a call; the docs bundle; the API contract; integration event, domain event) or in a code span; the words test reports any other bare use.
## B259 Scale and concurrency
- AC-1 A generated docs bundle of 200 intents and 2,000 bolts runs `status`, `next` and `check` within the time budgets the overview states, each a median of several runs.
- AC-2 Two merges started at once, and a builder's commit during a merge, end with one merge on the base and the other refused or done after it, never a half merge.
- AC-3 Both run in `node --test` at zero AI model tokens: code generates the docs bundle, and the CLI and git play the builders and merges; no agent, AI model or network call, so they run on every CI push.
## B261 An index entry without a description
- AC-1 `check` warns `HOUSE-INDEX-DESC` for each entry the generated indexes would write without a description, naming the index and the entry, so a subfolder of several docs gets its one line written once in the parent index; `aidlc index` keeps that line, and the warning goes.
## B262 Whole-tree checks
- AC-1 `check --tree` runs the path naming rules, the generated ones among them, and the slice checks over every tracked path, as errors in the gate's codes, so a path left from before a rule, such as a brownfield migration's leftover, is reported; without the flag, `check` leaves them to the gate, which counts only a bolt's changes.
## B263 Horizontal Units and superseded drafts
- AC-1 A Unit with no domain module serves its stories without slices (`UNIT-WORK`), since no slice can; a domain's Unit still names one per story.
- AC-2 A superseded draft decision needs no MADR sections (`DOC-SCHEMA`).
## B264 Intent re-reviews converge
- AC-1 After an intent review, the next one's brief names the commit the last one read, the diff command over the intent and its requirements, and each earlier finding by id; the reviewer answers those and reports new findings only on changed lines.
## B265 A rename keeps approvals
- AC-1 Rewriting link targets in an approved doc, as renaming the docs they point to requires, keeps its approval and is no `DOC-AMEND`; a changed word still stales it. A doc stamped by an earlier version keeps its approval through a link-only edit too.
## B266 A slice holds its own layers
- AC-1 The stack packs lay a domain out slice first ([0029](../decisions/0029-a-slice-holds-its-own-layers.md)): `sliceFolder` and `slicePaths` put each slice's layers in `<domain>/<slice>/<layer>/`, scaffold writes it, the Go, TypeScript and control-plane references follow it with their tests passing, and the slice checks read slices and layers from it.
- AC-2 An intent with a `baseline` needs no delivery bolt in its increment 1 (`INCR-SKELETON`); its top-level AC stays required.
## B267 Names derived from one set of coordinates
- AC-1 The registry merges the union of the kinds every layer names: the plugin's grammar, the stack pack's `naming` block, the architecture model's `model.grammar` and the project's `naming.grammar`; a kind any of them adds is printed by `aidlc name`, and one without `template` and `regex` is `PROFILE-NAMING` ([Naming coordinates](../design/naming-coordinates.md)).
- AC-2 Each kind with `files` generates a `GATE-NAME` rule, at the gate and in `check --tree` (a find rule on every tracked file's lines): the alternation of every name the registry composes when each token the kind needs is closed, else the kind's regex. `table` ships in `cli.json`; each stack pack says where its language writes `event` and `permission` names; slice folders stay `SLICE-NAME`'s. A misnamed name is refused and every composed name accepted.
- AC-3 A kind's `max` and `class` (from `naming.classes`) bound the names `aidlc name` prints; a `global` kind whose template and needs hold none of `system`, `org`, `instance` is a `PROFILE-NAMING` warning; an unknown class or scope an error.
## B268 The board on a Jira project
- AC-1 With a `jira` section in the profile (`site`, `project`, an optional `board`; `jira.acli` names another acli), `aidlc sync` projects the board's items onto the Jira project through acli, which owns the login: an intent is an Epic, a bolt a Story under its intent's Epic (a fix a Task), each bolt's `depends` a "Blocks" link, with the board's labels and a marker label, the ACs as a checklist, and the template's status map applied by a transition; a second sync with nothing changed makes no write ([Board on Jira](../design/board-jira.md)).
- AC-2 `board.issue`, when it is a Jira key, names the item and sync edits it; otherwise the marker label finds it, else sync creates it, after one more search; labels the plugin set and the plan dropped are removed and ones people add stay, and Jira's label rule is data.
- AC-3 The board extension derives the items for either board through the `boardItems` seam and the `jira` extension writes them, plugged into `boardSync` and `afterMerge` only when the profile has the section: with no `jira` section acli is never called, a merge's sync failure is a warning, `next` names sync while either board is behind, and the GitHub board is unchanged.
## B256 The gate codes split
- AC-1 The generated gate codes page is split by group, each page under its size cap; design docs that contradict each other are reconciled.
## B257 Old forms retired
- AC-1 Once the trial shows no project holds them, the v1 aliases (`units/`, `U-<n>`) are retired, with `upgrade` moving what a project still holds.

B255, B259 and B261 come before the trial runs, B262 from what it showed; B256 and B257 after them, shaped by what they show. The plugin's own code keeps its layout: restructuring tested code for consistency alone adds risk and no gain a user sees.
