# Goal
A project's architecture rules follow from what it declares, not from what someone remembers to write. In `resource-manager`:
- the layering was clean only by discipline;
- the front door linked the registry's internals and passed every check;
- the dependency graph read error-message prose as table names.

# Bolts
## B166 Boundaries from kinds
Hand-written boundaries were optional and absent ([Requirements and architecture](../design/architecture.md)).
- AC-1 The kind matrix in `cli.json` generates the boundaries at every `check` and gate (`ARCH-KIND`). Examples:
  - a domain reaches another domain only through its `client` or `events`;
  - a foundation kit never depends on a domain;
  - the core never depends on an extension;
  - a slice never imports another slice.
- AC-2 A project writes only exceptions, each an owner-approved decision listing its edges.
## B167 Layers point inward
- AC-1 With `layers` declared, `interface → application → model` and `infrastructure → model` are required, and any other edge is `ARCH-LAYER`.
## B168 Client, server and event surfaces
`registry/api` held both client and server, so importing the client linked the registry's internals ([Module surfaces](../design/module-surface.md)).
- AC-1 Another module may import only a module's `client` or `events`. `ARCH-API` reads surfaces when an end has no kind; with kinds on both ends `ARCH-KIND` decides. `module-surface.md` and `data-ownership.md` stay as detail docs, linked from `architecture-model.md` (folding them would pass its cap).
## B169 Transitive reach per runtime
- AC-1 `ARCH-REACH`: the transitive closure of a runtime's imports holds no internals of a domain it does not host.
## B170 Graphs the plugin can trust
- AC-1 Each stack pack ships a graph extractor; Go's is built on `go list -deps -json`. Data edges come from the domain's declared tables and migrations, not string literals.
- AC-2 A project-written graph is accepted only when it passes `GRAPH-SELFTEST` on the plugin's fixtures.
## B171 The Go stack pack
The method's launch talk warns that AI does domain-driven design badly in Go, and advises pointing it at reference code.
- AC-1 `aidlc scaffold domain|slice|foundation|pipeline|runtime|adapter …` writes the Go layout with names from the registry.
- AC-2 The pack's reference domain has one command and one query slice, fully tested, and passes every `ARCH-*` code. Cards link it.
- AC-3 Event types in a domain's `events` surface follow the grammar (`<Org>.<Service>.<Noun><PastTenseVerb>`, no version suffix), from M16 B165.
