# Goal
Every word, check, architecture model and reference shape follows the method and the reference architecture ([0023](../decisions/0023-words-follow-the-method-and-the-reference.md), [0024](../decisions/0024-vertical-slices-are-features-horizontal-layers.md)).

# Bolts
## B242 Words from the sources
- AC-1 The glossary names *vertical slice*, *horizontal layer*, *core*, *domain*, *extension*, *operation* and *internal layer* as 0023 defines them, and retires "slice" for one command or query.
- AC-2 `aidlc name` and `aidlc scaffold` take `operation`; the stack packs, their references, the constitution's rule 9 and the shipped messages use the same words; a test fails on shipped text that writes "slices" without "vertical".
## B243 A Unit's artefacts
- AC-1 An intent lists its Units under `# Units`, as the method's Mob Elaboration and Units Generation give them. Each Unit has a name, a kind (`service`, `spec`, `ui`, `packaging` or `library`), the modules it changes, its responsibilities, its user stories, its non-functional requirements, its risks, its measures citing the intent's success measures, and the Units it depends on; its integration points, deployment model, complexity, bolts and a PRFAQ are optional. The glossary maps the method's Unit to this; the domain docs stay the system-wide Domain Design.
- AC-2 Each story has a stable id `US<g>.<s>` and belongs to at least one Unit, and each Unit has at least one story; the dependencies are acyclic and name only Units of the intent; each bolt's modules belong to a Unit of its intent. A draft intent that breaks one is a finding that blocks its approval.

## B244 Vertical slices are features
- AC-1 The glossary defines the vertical slice as the code of one business feature or use case, cutting through every horizontal layer it needs and naming the use case it serves, and the horizontal layer as code grouped by one technical concern, shared by every feature ([0024](../decisions/0024-vertical-slices-are-features-horizontal-layers.md)); *operation* and *internal layer* are retired.
- AC-2 `aidlc name slice` and `aidlc scaffold slice` name and write a slice; an architecture model's extension declaration is its `extension`, declared under each module's `declares`; rule 9 of the constitution and the packs' references use the same words.

## B245 Vertical slices checked
- AC-1 `SLICE-IMPORT`, `SLICE-ENTRY` and `SLICE-PLACE` read the pack's graph: no slice imports another, a slice is entered only from its domain's interface layer or a declared integration event consumer and from somewhere, every file of a layered domain sits in one layer and every file under application in one slice, and no declared layer or slice is empty ([Vertical slices checked](../design/vertical-slices.md)).
- AC-2 `SLICE-SURFACE`, `SLICE-STORY` and `SLICE-TEST`: the slice folders equal the domain doc's commands and queries, each naming its use case and citing the stories it serves as `I-<n>:US<g>.<s>`; each story of an approved unit of work is cited by a slice; each slice has a test in its folder or one that imports it. At the gate a finding counts only where the bolt changed a file.
## B246 Slices named, routed and delivered whole
- AC-1 A slice is named verb and noun from the naming registry; every route maps to exactly one slice through a unique API operation id equal to its name.
- AC-2 A bolt that adds a slice also adds its route, its test and its surface line.
