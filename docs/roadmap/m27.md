# Goal
Every word, check, model and reference shape follows the method and the reference architecture ([0023](../decisions/0023-words-follow-the-method-and-the-reference.md), [0024](../decisions/0024-vertical-slices-are-features-horizontal-layers.md)).

# Bolts
## B242 Words from the sources
- AC-1 The glossary names vertical slice, horizontal layer, core, domain, extension, operation and internal layer as 0023 defines them, and retires "slice" for one operation.
- AC-2 `aidlc name` and `aidlc scaffold` take `operation`; the stack packs, their references, the constitution's rule 9 and the shipped messages use the same words; a test fails on shipped text that writes "slices" without "vertical".
## B243 A Unit's artefacts
- AC-1 An intent lists its Units under `# Units`, one per domain it changes, as the method's Mob Elaboration gives them: each Unit's user stories (every story in exactly one Unit, each story a vertical slice), its non-functional requirements, its risks, its measures citing the intent's success measures, the Units it depends on (no cycles) and its bolts. The glossary maps the method's Unit to this, and the domain docs stay the system-wide Domain Design.
- AC-2 A bolt outside increment 1 belongs to the Unit of its domain; a draft intent missing a Unit's part is a finding that blocks its approval.
## B244 Vertical slices are features
- AC-1 The glossary defines the vertical slice as the code of one business feature or use case, cutting through every horizontal layer it needs and naming the use case it serves, and the horizontal layer as code grouped by one technical concern, shared by every feature ([0024](../decisions/0024-vertical-slices-are-features-horizontal-layers.md)); operation and internal layer are retired.
- AC-2 `aidlc name slice` and `aidlc scaffold slice` name and write a slice; a model's vertical contract is its `extension`, declared under each module's `declares`; rule 9 of the constitution and the packs' references use the same words.
