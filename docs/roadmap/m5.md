## U40 Generated files in a scope
A scope that names a generated file without its source, or an untracked copy instead of the tracked output, stops the builder.
- AC-1 The profile maps generated outputs to their sources: `generated: [{ "outputs": [<glob>], "sources": [<glob>] }]`.
- AC-2 Plan lint reports `PLAN-GENERATED` for a live unit whose scope overlaps an entry's outputs but none of its sources, or its sources but none of its outputs, naming the globs it lacks.
- AC-3 It also reports a scope entry naming a file that exists in the working tree but git does not track (untracked or ignored): a builder cannot commit it. A new file the unit creates does not exist yet and passes.

## U41 Fresh context per intent
A lead that carries one intent's context into the next fills its window and loses accuracy.
- AC-1 When an intent is released and no unit of another intent is in flight, `next`'s owner line asks the owner to clear the lead's session (`/clear`) before the next intent; work on disk resumes through the status hook.
- AC-2 `status` shows the same hint while no unit is in flight and every intent is released.

## U42 Refused owner commands
An owner command the CLI refused must not count in the retro as one that ran.
- AC-1 An owner prompt whose command ended with a non-zero exit is recorded as `refused`, not `ran`.
- AC-2 The retro lists refused owner commands apart from those that ran.

## U43 Vertical slices
Nothing checks that an intent ends in an end-to-end vertical slice.
- AC-1 Plan lint reports `PLAN-SLICE` for an intent none of whose units has an AC at the profile's top level: the last level in `levels` with a `run`. With no level that runs, it reports nothing. An intent can waive it with `slice: "<why no end-to-end AC>"` in its frontmatter, for docs or tooling work.
- AC-2 It also reports a unit whose `modules` name two or more modules while all its ACs are at the first level, since behaviour that crosses a module needs an integration test or higher ([Grid](../design/grid.md#tests)).

## U44 Skipped tests do not pass
A tagged test that needs a database skips without one, and the gate takes the skip for a pass.
- AC-1 A level may name what its run needs: `levels.<level>.needs: ["<ENV_VAR>"]`. The gate refuses the run with `GATE-RUN` naming each one unset, before it runs, instead of letting its tests skip.
- AC-2 A level may name how its runner reports a skip: `levels.<level>.skip: "<regex>"`. A level run or a proof-revert run whose output matches it fails, with `GATE-SKIP` and the matching line.

## U45 Clear line after the clear
`next` must not ask for a clear that already happened.
- AC-1 The status hook records a `/clear` (SessionStart `source: clear`). Once every intent is released, `next` asks for the clear only when none happened since the last unit merge; after it, `next` asks to elaborate the next intent.

## U46 Worktrees removed after a merge
A merge that keeps the builder's worktree leaves a cleanup step for `next` to name.
- AC-1 After a merge, a builder worktree whose tracked files are clean is removed even when the host locked it, with the lock's force; one with uncommitted tracked changes is kept and named, as now.
