## U40 Generated files in a scope
From the [M4 pilot 3](../pilot/m4-3-report.md): a scope named a generated file without its source, then an untracked copy instead of the tracked output.
- AC-1 The profile maps generated outputs to their sources: `generated: [{ "outputs": [<glob>], "sources": [<glob>] }]`.
- AC-2 Plan lint reports `PLAN-GENERATED` for a live unit whose scope overlaps an entry's outputs but none of its sources, or its sources but none of its outputs, naming the globs it lacks.
- AC-3 It also reports a scope entry naming a file that exists in the working tree but git does not track (untracked or ignored): a builder cannot commit it, as with the untracked copy in the pilot. A new file the unit creates does not exist yet and passes.

## U43 Vertical slices
The owner asked whether the loop ensures end-to-end vertical slices (2026-10-24); nothing checked it.
- AC-1 Plan lint reports `PLAN-SLICE` for an intent none of whose units has an AC at the profile's top level: the last level in `levels` with a `run`. With no level that runs, it reports nothing. An intent can waive it with `slice: "<why no end-to-end AC>"` in its frontmatter, for docs or tooling work.
- AC-2 It also reports a unit whose `modules` name two or more modules while all its ACs are at the first level, since behaviour that crosses a module needs an integration test or higher ([Grid](../design/grid.md#tests)).

## U44 Skipped tests do not pass
From the [M5 pilot 1](../pilot/m5-report.md): a tagged test that needs a database skipped without one, and the gate took the skip for a pass.
- AC-1 A level may name what its run needs: `levels.<level>.needs: ["<ENV_VAR>"]`. The gate refuses the run with `GATE-RUN` naming each one unset, before it runs, instead of letting its tests skip.
- AC-2 A level may name how its runner reports a skip: `levels.<level>.skip: "<regex>"`. A level run or a proof-revert run whose output matches it fails, with `GATE-SKIP` and the matching line.
