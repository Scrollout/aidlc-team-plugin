## U52 Level runs at init
- AC-1 `init --run <level>=<command>`, repeatable, writes `levels.<level>.run` into the profile; a level the profile does not know or a value without `=` exits 64.
- AC-2 Without `--run`, `init` writes no `run` and prints, for each command it detects from the `cli.json` map, the flag to offer the owner (`--run unit=npm test`); the skill asks the owner for each level's command before running `init`.
- AC-3 Plan lint reports `PLAN-RUN`, a warning, while no level in the profile has a `run`.

## U53 Constitution at init
- AC-1 `init` writes `<bundle>/constitution/principles.md` of type `Principles`, unless the file exists or the bundle is adopted; every code it names is one the CLI defines, and it has a section for the project's own rules.
- AC-2 After `init`, the bundle's indexes list the constitution and `aidlc check` passes; AGENTS.md points to the constitution and stays within its 60 lines.

## U54 Upgrade adds what is missing
- AC-1 `upgrade` adds each `.aidlc/templates/docs/` template the project lacks, and the constitution when the bundle holds no doc of type `Principles`, regenerating the indexes; it overwrites nothing and names each file it added.

### U55 Mutations in the report
- AC-1 For a unit with no change outside the test paths, `aidlc report` refuses (exit 64) a `done` report unless it lists one mutation per AC (`ac`, `path`, `find`, `replace`), each `path` outside the test paths and the unit's diff, and each `find` occurring exactly once in that file on the unit branch; the message names what is missing.
- AC-2 The builder prompt says when and how to list mutations; the card shows a reported unit's mutations, and the reviewer prompt says to send back one that does not break the behaviour its AC names.

### U56 Gate proves back-fill tests
- AC-1 For such a unit, not in the quick lane, the gate applies each mutation alone in its trial tree, runs the level of its AC and restores the file; a level that still passes or skips refuses the merge as `GATE-PROOF`, naming the AC.
- AC-2 An AC without a mutation, or one whose `find` no longer matches exactly once, refuses as `GATE-PROOF`; a passing proof writes `Proof: mutation <levels>` in the merge trailer.

### U57 Back-fill without release steps
- AC-1 An intent whose units' scopes all lie inside the levels' test paths gets no `PLAN-RUNBOOK`, and once its units are merged it is released: `next` runs no deploy check and offers no release.
- AC-2 A merge proved by mutations prints, for each AC, the level its mutation failed.

### U58 Fix unit lints itself
- AC-1 `aidlc fix` writes the unit, runs plan lint on it and prints each finding with its fix, exiting 1 while there is one; `next`'s lines that ask for a fix unit show a test location from the profile in their `--scope` example.

### U59 Park a merged intent
- AC-1 `aidlc hold I-<n> <reason>` on a merged intent stops `next` from naming its deploy check, release or fix, and names the hold with its reason as the owner's step instead; `hold I-<n> off` resumes them. A failed smoke is still a stop.

### U60 Quick merges run no levels
- AC-1 A quick-lane merge runs no level: only the commands its ACs name, the module checks it touches and the docs check; its trailer reads `Tested: none`. Other lanes still run every level in full.
