# Goal
No value in the CLI's code, and none in the code of a project the plugin governs: every name, pattern, default, mapping, message and doc grammar is data, several values are a structured object, and the CLI serves its answers and actions as JSON and JSON-RPC 2.0 ([Values as data](../design/values.md), principle 11).

# Bolts
## B235 The core's values
- AC-1 The guard test fails on a literal in `plugin/cli/aidlc.mjs` or `plugin/cli/lib/` that is no data key, message key, check code or listed tool protocol.
- AC-2 Every such literal of the core lives in `cli.json`; the behaviour is unchanged.
- AC-3 No value of `cli.json` is a delimited string the code splits: several values are an array or an object.
## B236 The extensions' values
- AC-1 The guard covers `plugin/cli/extensions/`; every literal of an extension lives in its `extension.json`.
## B237 The board as a template
- AC-1 `board.json` (and a project's `.aidlc/board.json`) describes each item kind's title, body, labels, type, milestone, parent, assignees and relationships, and the Project's fields with their types; `sync` renders it.
- AC-2 `depends` syncs as blocked-by links; iteration fields are written; per-bolt assignees apply; labels the plugin set that no longer apply are removed; a Project field of the wrong type is refused before any write.
## B238 No hard-coded data in projects
- AC-1 The project constitution holds the rule; the builder keeps values in the project's data files and the reviewer reports a literal value.
- AC-2 `VALUE-LITERAL` at the merge gate: a string literal on an added line of a source file, outside tests, `values.data` and the pack's and the profile's allowed protocol, is a finding; each stack pack names its language's string literal.
## B239 Structured answers
- AC-1 `status`, `next`, `lane`, `graph`, `models` and `check` return their values as `data`, and their text is rendered from it; `next` serves its action as a JSON-RPC 2.0 request object.
- AC-2 `aidlc rpc` answers JSON-RPC 2.0 requests from stdin, one per line or a batch, with `{ code, findings, output, data }` as the result, `-32601` for an unknown method, `-32602` for a usage error, and owner commands refused.
## B240 The lifecycle as data
- AC-1 The bolt and intent machines are data: each transition is `{ from, to, on, when }`, `when` a named guard with its own test; the states `status` and `next` derive are unchanged.
- AC-2 `next` walks `next.order` and serves the first action whose guard holds as a JSON-RPC 2.0 request; the gate's checks, the review focuses and the hook chain are ordered stage lists a profile can extend but not shorten.
## B241 One layout
- AC-1 Templates, personas, models and packs each sit in their own folder at the top of `plugin/`, a model holding its reference code; one resolver serves every lookup, and a test fails on a file outside its package or a lookup around the resolver.
- AC-2 `init` and `upgrade` pin every package under `.aidlc/bin/`; a project file at the same path under `.aidlc/` wins; `upgrade` moves `.aidlc/packs/` once.
