# Goal
No value in the CLI's code, and none in the code of a project the plugin governs: every name, pattern, default, mapping, message and doc grammar is data ([Values as data](../design/values.md), principle 11).

# Bolts
## B235 The core's values
- AC-1 The guard test fails on a literal in `plugin/cli/aidlc.mjs` or `plugin/cli/lib/` that is no data key, message key, check code or listed tool protocol.
- AC-2 Every such literal of the core lives in `cli.json`; the behaviour is unchanged.
## B236 The extensions' values
- AC-1 The guard covers `plugin/cli/extensions/`; every literal of an extension lives in its `extension.json`.
## B237 The board as a template
- AC-1 `board.json` (and a project's `.aidlc/board.json`) describes each item kind's title, body, labels, type, milestone, parent, assignees and relationships, and the Project's fields with their types; `sync` renders it.
- AC-2 `depends` syncs as blocked-by links; iteration fields are written; per-bolt assignees apply; labels the plugin set that no longer apply are removed; a Project field of the wrong type is refused before any write.
## B238 No hard-coded data in projects
- AC-1 The project constitution holds the rule; the builder keeps values in the project's data files and the reviewer reports a literal value.
- AC-2 `VALUE-LITERAL` at the merge gate: a string literal on an added line of a source file, outside tests, `values.data` and the pack's and the profile's allowed protocol, is a finding; each stack pack names its language's string literal.
