# Goal
Show on two real projects that v2 keeps a project from slipping, sliding, drifting or mixing, with numbers rather than impressions.

# Bolts
## B198 Branches and worktrees with no live bolt
A project can hold stale agent worktree branches and locked worktrees long after their work ended ([Paths](../design/paths.md)).
- AC-1 `HYGIENE-BRANCH` lists every branch and worktree with no live bolt, and the brownfield R0 step removes them with the owner's yes.
## B199 A brownfield project migrates
- AC-1 A brownfield intent takes a project on method v1 to v2:
  - kinds and surfaces for every module;
  - registered names in place of names invented on the spot;
  - the domain layout;
  - its decisions that v2 contradicts reconciled by superseding decisions.
- AC-2 Its increment 1 passes smoke on dev.
- AC-3 A shipped model that fits it ([M24](m24.md)) is applied: its modules matched to the model's layers and kinds, the gaps planned as increments, each with the owner's yes.
- AC-4 Each plugin change found on the way is its own bolt here.
## B200 A fresh project to increment 2
- AC-1 A new project goes from a plain-prose request (`aidlc intake`) and a model to increment 2 passing smoke on its target on v2 alone.
## B201 The program measured
- AC-1 A trial report records each success measure of the v2 plan on both projects:
  - no vocabulary change inside an intent;
  - no module without a kind, and no unregistered name;
  - every seeded decision contradiction caught before approval, and no bulk approval of one-way doors;
  - delivered figures equal to the recomputed ones;
  - no compile-only proof, and no fix bolt with more than one AC;
  - every security finding disposed of by the owner;
  - the bundle clean at every merge;
  - lead time, predictability, and conflicts by binding kind.
- AC-2 The legacy aliases' expiry is set from it.
