# Goal
An intent is done when it is deployed and its smoke check passes, not when it is merged; a failed release becomes work, not a surprise ([Deployment and operation](../design/operations.md)).

# Choices
([Deployment and operation](../design/operations.md#choices)): the owner runs deploy and release; a failed smoke stops for the owner's rollback; one target; a runbook per intent and retro feedback are in, observability and SLO checks are out.

## U47 Deploy check before release
- AC-1 With `deploy.check` in the profile, once an intent is merged `next` runs nothing itself but names `aidlc deploy check I-<n>` for the lead; the command runs each `deploy.check` on the base and records the result with the base commit.
- AC-2 `next` offers the release only when the last deploy check passed on the current base; a failure names the command and the fix (`aidlc fix … --scope …`).

## U48 Release as an owner step
- AC-1 `aidlc release I-<n>` runs `deploy.run` (when set) and then `release`, records each exit, and is an owner command: the guard asks the owner, as for `approve`.
- AC-2 `next`'s release line names it with the words to type (`release I-<n>`); without `deploy` or `release` in the profile, the release line stays as today (tag with the owner).

## U49 Smoke and rollback
- AC-1 After a release, `deploy.smoke` runs (from `aidlc release`); a pass marks the intent released, and the record keeps the smoke output.
- AC-2 A failed smoke is a ⛔ stop: `next` names `aidlc rollback I-<n>` as the owner's step (it runs `deploy.rollback`), and drafts a fix unit from the smoke output with `aidlc fix`.

## U50 Runbook per intent
- AC-1 When the profile has `deploy`, plan lint reports `PLAN-RUNBOOK` for an intent that links no doc of type `Runbook`; `init` ships a runbook template (how to roll back, what to watch, who to call).

## U51 Feedback in the retro
- AC-1 The retro lists each failed deploy check, smoke and rollback of the intent, with the fix units they started.
