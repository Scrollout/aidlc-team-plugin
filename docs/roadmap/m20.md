# Goal
The pilots start from a plugin with no leftovers, and its docs and diagrams can't drift from what it enforces. Removal happens in each milestone as replacements land. This milestone is the sweep and its checks ([0013](../decisions/0013-a-deterministic-ai-dlc.md)).

# Bolts
First the CLI becomes a library ([0017](../decisions/0017-the-cli-is-a-library-with-extensions.md), [Library and extensions](../design/library.md)), so the sweep runs on the new layout.
## B202 Foundation kits
- AC-1 `lib/foundation/` holds `data`, `git`, `text`, `yaml`, `glob`, `profile`, `store` and `seams`, which import nothing above them.
## B203 Seams, no cycles
- AC-1 Plan rules, doc checks, gate checks, merge writes, status lines, card sections, proof patterns and the board's hooks into the core go through `seams`. The CLI's own graph has no cycle.
## B204 Domains and a public entry
- AC-1 `lib/domains/` holds one module per bounded context. `state.mjs` splits into `approval`, `flow` and `review`.
- AC-2 `lib/index.mjs` is the public entry, and the tests import from it.
## B205 Adapters and runtime
- AC-1 `aidlc.mjs` builds its command table from the domains and the loaded extensions. An adapter speaks to an outside system and depends only on foundation kits.
## B206 Extensions
- AC-1 `board`, `contracts` and `stacks` move to `plugin/cli/extensions/<name>/` with their data in `extension.json`, enabled by a profile key. The core imports none of them.
## B207 The plugin follows its own architecture
- AC-1 This repo's profile gives each layer and extension a kind. `check` runs `ARCH-KIND`, `ARCH-LAYER` and `ARCH-CYCLE` on the CLI's own graph, and they pass.
- AC-2 The budget test counts the core and each extension against their own limits.

Then the formats follow published standards ([0018](../decisions/0018-standard-formats-over-home-made-ones.md), [Standard formats](../design/standards.md)).
## B208 Decisions in MADR 4.0
- AC-1 The decision template is MADR 4.0's. Approving sets `status: accepted` and `date`, and a successor sets the old one to `superseded by ADR-<NNNN>`. A draft decision in a v2 project lacking a required section is `DOC-SCHEMA`.
- AC-2 The plugin's own decisions are in MADR form.
## B209 Acceptance criteria as Given/When/Then
- AC-1 The templates write ACs as Given/When/Then. In a v2 project, under method 5, an AC with no `when` and `then` is `PLAN-AC`.
## B210 Requirements in EARS
- AC-1 The requirement template states the requirement in an EARS pattern. A draft requirement in a v2 project whose statement fits none is `PLAN-REQ`.
## B211 Keep a Changelog and SemVer
- AC-1 The plugin keeps `CHANGELOG.md` per Keep a Changelog 1.1.0, with an entry for each release, and a test holds it to `plugin.json`. `init` writes a project's `CHANGELOG.md`.
## B212 arc42 and C4
- AC-1 The system template follows arc42's 12 sections. In a v2 project a draft system doc missing one is `DOC-SCHEMA`, and the generated maps name their C4 level.
- AC-2 The plugin's own architecture has an arc42 page and a generated C4 component view of the CLI.

## B191 Diagrams generated from the rules
The diagrams in `overview.md`, `grid.md`, `state.md`, `intent-states.md` and the README are drawn by hand.
- AC-1 Generated blocks are rewritten by `aidlc docs`, and a golden test fails on any difference (`DOC-DIAGRAM`). They cover:
  - the canonical model;
  - the workflow with its pathways;
  - intent and increment states;
  - the kind matrix and the layers inside a domain;
  - the bundle's doc types and their relations;
  - the naming grammar;
  - the gate's checks in order.
- AC-2 The hand-drawn diagrams they replace are deleted.
## B192 Every code documented once
- AC-1 Every check code in `cli.json` is documented in exactly one design doc, and every code a doc names exists (`DOC-CODE`).
## B193 The old words are gone
- AC-1 `TERM-SYNONYM` runs on this repo. No retired word appears in its old sense in `plugin/`, `docs/` or `tests/`: unit for a work item, slice for a delivery step, bundle, component. The skill and agent prompts stay within 3 KB each.
## B194 Lessons, not reports
- AC-1 `docs/pilot/` becomes one `lessons.md`, each lesson naming the rule or check that now holds it. The 17 reports are deleted; git keeps them.
- AC-2 `later.md` holds only ideas still open.
## B195 No dead code
