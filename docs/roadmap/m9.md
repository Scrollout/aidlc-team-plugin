## U71 CI on the base
- AC-1 `aidlc ci wait` polls the GitHub Actions runs of the pushed base head every `ci.interval` seconds up to `ci.wait`, records the sha, state (green, red, pending, none) and runs in `.git/aidlc/ci.json`, and exits 1 on red, naming each red run's log command; it is refused on a base not pushed, or without `ci.wait` or `github.repo`.
- AC-2 With `ci.wait` set, before `next` starts a builder: an unpushed base gives `aidlc push`, and no record or a pending one for the base head gives `aidlc ci wait`; merges and reviews still come first. Without `ci.wait`, `next` is unchanged.
- AC-3 A red record for the base head comes first in `next` after a cut-off merge and a failed release or smoke: without a live fix unit it asks for `aidlc fix` from the red runs; while red only units without an intent build or merge, and other units' reviews go on.
