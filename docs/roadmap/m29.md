# Goal
A vertical slice merges whole: every layer its use case needs, from the screen to the migration, planned where its story is written and checked where its code is merged ([Building a slice](../design/slice-method.md), [0026](../decisions/0026-a-slice-declares-the-layers-it-needs-and.md)).

# Bolts
## B250 Declared cuts
- AC-1 Decision 0026 and the glossary define a slice's scope, cuts, own code (its screen, route and handler), shared layers (its migration among them), data, entry, permission and integration, governance running on the entry; the glossary's words to avoid send each clashing word (schema, action, mode, part, contract, bundle) to the one it means.
- AC-2 Method 13: a `# Surface` line and a Unit of work's `Slices` line carry the slice's cuts, data, entry, `permission`, `async`, events and calls; `UNIT-WORK` and `SLICE-SURFACE` report a cut the pack does not list, or none, a data node its domain neither owns nor shares, an entry that is no `runtime` module, a `permission` the registry does not compose, an event in no domain's `events` surface, a call to no client or adapter, and a story served through a screen whose slice has no `ui` where the pack has one.
- AC-3 A model's slice carries `cuts`, `data`, `entry`, `permission`, `async`, `emits`, `consumes` and `calls`, and each runtime of the model what it `applies` to its slices, its governance stages among them; `MODEL-FORMAT` checks them, `models apply` writes them into `# Surface`, `models apply` prints increment 1 from the slice that cuts through every layer, `models gaps` lists a missing slice, cut, data node, entry or integration, and intake lists each fitting model's slices with their cuts and hand-offs.
- AC-4 The intent and domain templates, the product analyst and the architect carry the cuts, the domain template's `Events:` line naming the integration events other domains consume; the example control-plane model declares what each runtime applies, and each slice's cuts, data, entry and integrations.
## B251 Packs and scaffold
- AC-1 Each pack lists `slicePaths`, where a slice's own code sits in each layer (`interface/<slice>` among them), `ui` where the stack has one; the names come from the registry; `SLICE-PLACE` accepts the `client` and `events` surface folders beside the layers.
- AC-2 `scaffold slice` writes a file and a test for each cut with own code and changes nothing that exists; each pack's reference and the example model's reference put each slice's route under `interface/<slice>`, declare their slices' cuts and pass every slice check.
## B252 Card and gate
- AC-1 The bolt template carries each slice with its cuts; `PLAN-SLICE` reports a bolt whose scope misses a cut's path.
- AC-2 The card lists each slice's cuts as ordered test-first steps; the builder, the reviewer and the skill follow them.
- AC-3 `SLICE-DELIVER` refuses a bolt whose diff leaves a cut unchanged, naming the layer; the board's bolt carries each slice's cuts, data and entry, and a field counting its cuts done.
- AC-4 `SLICE-DATA` refuses a data edge from a slice's code to a node it does not declare; `SLICE-ROUTE` refuses a slice whose route is wired outside the runtime of its entry; `SLICE-INTEGRATE` refuses an import of another domain's client, an adapter or an event type the slice does not declare, and a declared integration its code does not reach; `SLICE-GOVERN` refuses a slice with no `permission` behind an entry that authorizes, and one that authenticates or authorizes itself.
## B260 The ui cut's forms
- AC-1 A pack's `slicePaths.ui` maps each form it has, `cli`, `web` and `template`, to its path; a declaration cuts `ui.<form>`, or `ui` for every form the pack has; `UNIT-WORK` and `SLICE-SURFACE` report a form the pack does not have.
- AC-2 `scaffold slice` writes each form's own code and test; `PLAN-SLICE` and `SLICE-DELIVER` hold each form as a cut; a template form names the slice's resource type in the template schema and the deployment that applies it calls the slice's route.
## B253 Proof and reports
- AC-1 `SLICE-TEST` requires a test at a level whose `proves` holds `route` that names the slice's route, and one at a level whose `proves` holds `handoff` for each declared event and call; a consumer's test names the publisher, and an `async` slice's test follows the status to a terminal state; a `route` test sees a request without the slice's permission refused before its handler, and a business rule has its own refusal test.
- AC-2 `INCR-SKELETON` requires increment 1's first slice to cut every layer the system's pack has.
- AC-3 `status`, `next`, the codebase map and the trace show the hand-offs between slices across domains, and each slice as planned, partial or done, layer by layer; the trace lists each slice's `permission` as the permission catalogue; the retro counts refusals by layer.
