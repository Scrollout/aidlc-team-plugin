# Goal
Every name in a project is a fixed grammar over registered tokens. "Front door", "portal", "store" and "endpoint" were names invented on the spot. Here they become domain codes and words from closed vocabularies. The API and event grammar is the reference cloud's ([0014](../decisions/0014-the-reference-clouds-api-and-event-conventions.md)).

# Bolts
## B160 The naming registry
Names were free text checked by hand-written regexes, one project at a time ([Names](../design/names.md)).
- AC-1 The profile's `naming` holds `tokens` (org, system, zone), `domains` (code, full name, abbreviation), `vocabularies` (role, env, pipeline, foundation, verb) and `banned`. A malformed registry is `PROFILE-NAMING`.
- AC-2 `init` asks for the system code, org and zone, and registers a domain from its domain doc's `code`.
## B161 Names printed by the CLI
A builder typed each name and learned the convention only when a check failed ([Names](../design/names.md)).
- AC-1 `aidlc name <kind> [--domain d] [--role r] [--env e]` prints the name from the grammar in `cli.json`. It covers folder, package, slice, operation ID, path, permission, event type, schema, table, migration, deployable, image, namespace, host, metric and config key.
## B162 Rules generated from the registry
Projects wrote their own regexes, which drifted from their docs ([Names](../design/names.md)).
- AC-1 `GATE-NAME` rules are generated from the grammar and registry, and the hand-written `names` authoring path is removed.
- AC-2 A token not in the registry is `NAME-UNREGISTERED`; a banned word in a new path or identifier is `NAME-BANNED`.
- AC-3 `names.md` is replaced by `naming.md`.
## B163 One term, one meaning
The same concept had several names across docs and code ([Names](../design/names.md)).
- AC-1 The domains' glossaries generate `naming/glossary.md`.
- AC-2 A registered synonym used in code or doc bodies is `TERM-SYNONYM`.
## B164 The card names what the bolt will create
- AC-1 A bolt card's `## Names` lists the exact names the bolt will create, generated in advance from its binding and scope.
## B165 Contracts follow the reference grammar
- AC-1 `CONTRACT-NAME` checks a project's published OpenAPI output for the following, with the reference cloud's linter regexes where they exist:
  - path grammar and even PUT segments;
  - `Noun_Verb` operation IDs;
  - `api-version` format;
  - lowerCamelCase properties and PascalCase enums;
  - the resource envelope with `systemData`;
  - `value` plus `nextLink`;
  - the error envelope.
- AC-2 It checks event type and CloudEvents attribute rules in the same way.
