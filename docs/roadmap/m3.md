# Goal
A builder writes code the way the project does, "test first" is checked rather than asked for, and the grid reaches Deployment and Operation.

# Why
A review of common advice on how agents write clean code (owner's brainstorm, 2026-10-23) against this plugin found deterministic gates, plan-first units and capped fix loops already in place, and three gaps. Builders run without `CLAUDE.md` and their cards carry no `.aidlc/rules/`, so a project's conventions never reach them. The [M2 pilot](../pilot/m2-interventions.md) builders were not red-first, and nothing checks it. No review looks for needless code, the most common way agent code goes wrong. Numeric style limits in prompts were rejected: models follow them loosely and they cost tokens on every run; projects get them from their own linters, which the gate already runs.

# Exit criteria
Draft, for the owner to settle when M3 is planned in full:
- A pilot unit's card carries the project rules, and its builder follows one the pilot project sets.
- A test that passes without its unit's change refuses the merge.
- The CLI and prompts stay within the budgets in [Overview](../design/overview.md).

# Candidate units
In priority order; the owner plans the units and their ACs.
| Item | Scope | Why first or later |
|---|---|---|
| Project rules on the card | `.aidlc/rules/*.md` (all but focus files) rendered into the card, within its 6,000-char cap | Biggest gap, cheap: every project convention is lost today |
| Proof-revert | the gate reverts the unit's non-test change on a trial worktree and requires each tagged test to fail | Makes "test first" real; the M2 pilot builders skipped it |
| Simplicity in the general review | one evidence-based check: an existing helper rewritten, unused code, a one-use abstraction, each with path and line | Only if the next retro shows the rules on the card do not cover it |
| Complexity check for this repo | a zero-dependency test in `tests/` that checks function size in `plugin/cli/` | Only if it fits zero dependencies; the line budget covers most of it |
| Advisor ([0010](../decisions/0010-research-and-advice.md) option 3) | a strong-model agent drafting the decision from a research digest | Only if the lead's recommendations prove weak |
| Carried from M2 | security content patterns, `reserve` and `clean`, `check --staged`, org rule packs, Domain row templates for the full lane, Deployment and Operation rows, the CI evaluator agent, other agent hosts | Planned with the owner |
