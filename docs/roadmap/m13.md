# Goal
A project builds vertical slices that ship to dev one by one, every card says what it is and why with a path for everything it names, and a repeated call never changes the record ([Log](../log.md)).

# Units
## U117 Every slice cut before an intent is done
An intent counted as released with half of its slices unbuilt, because the built ones shipped no product file, and its data ownership never reached the gate ([Grid](../design/grid.md#slices)).
- AC-1 An intent with a `# Slices` line naming no unit is not merged or released while its units are merged; `next` asks to cut that slice's units.
- AC-2 The intent template has a `# Slices` section.
## U118 Slices stay vertical
Plans drift from vertical end-to-end slices: an intent cut as layers puts the walking skeleton behind them, and slices wait behind unrelated fix units, chained only because `PLAN-SCOPE` demands a `depends` for any shared file ([Grid](../design/grid.md#slices), [Plan lint](../design/plan-lint.md)).
- AC-1 `PLAN-SLICE` reports an intent with more live units than `plan.sliceUnits` without `# Slices`, a live unit on no slice line, a slice whose units have no top-level AC, a slice wider than `plan.sliceUnits` (default 3), and a unit waiting on a later slice.
- AC-2 `PLAN-SLICE` reports a unit of an intent waiting on a fix unit not yet merged.
- AC-3 `PLAN-SCOPE` asks for `depends` only between overlapping units of one intent; `next` never starts a unit whose scope overlaps one started and not merged, and puts intent units before fix units at the same priority.
## U119 The card cap counts lines
A unit passed `check` while `card` refused it: PLAN-CARD sized only unapproved units, and a char cap pushes the lead to squeeze wording where a line cap does not ([Unit card](../design/bolt-card.md)).
- AC-1 The card cap is 100 lines; `card`, PLAN-CARD and the budget test count lines.
- AC-2 PLAN-CARD sizes every unit not yet merged, approved ones too.
## U120 A pipe after cd keeps the folder
`cd ~/infra && git push -q origin main 2>&1 | tail -3` was refused as a raw push of the base, because any pipe or `||` in the command voided every `cd` ([Hooks](../design/hooks.md#wiring)).
- AC-1 A `cd` is unresolved only in a command with a subshell or when the `cd` itself sits in a pipeline or background job; a pipe or `||` after it keeps its folder.
## U121 Each slice ships to dev
Deploy steps ran once per merged intent, so its slices reached dev only after the last one merged ([Deployment and operation](../design/operations.md)).
- AC-1 An intent with `# Slices` whose newest merged slice is not in its last passing release runs the deploy check, the owner's release and smoke while its next slices build; `deploy` and `release` accept it.
- AC-2 An intent is released only by a release whose base holds every merge.
- AC-3 While builders run, `next` names a due release step instead of waiting.
## U122 A built slice names its merged units
An intent built before slice lines named units came back with `next` asking to cut units for slices long built ([Grid](../design/grid.md#slices)).
- AC-1 The cut-slices line also asks to name the merged units that already built a slice.
## U123 A slice ships only its intent's units
`next` offered a release of a draft intent with no units, because its slice line cites another intent's merged unit ([Deployment and operation](../design/operations.md)).
- AC-1 A slice is due to ship only from merged units of its own intent; a cited unit of another intent counts for nothing.
## U124 A manifest edit asks for sources only for a pin
Listing the Makefile, CI workflow and deployment files that pin images in `deps.manifests` would make every edit to them need a sourced dep ([Current dependencies](../design/dependencies.md)).
- AC-1 `report` asks for `deps` only when the diff adds a line matching `deps.pin` to a manifest.
## U125 Each reviewer in flight is waited for
One focus's review recorded its pass while another still ran, and `next` asked for the running one again ([In flight](../design/in-flight.md)).
- AC-1 The reviewing mark counts the reviewers launched; `review record` removes one, so `next` waits while any is in flight.
## U126 The intent is the vertical spec
AI-DLC's spec architecture puts vertical specs first, extracts horizontal ones on reuse and keeps the why beside each rule; the grid named `capabilities/` docs nothing writes ([Grid](../design/grid.md)).
- AC-1 The intent template has `# Risks` and asks each slice's rule or limit for its why; the grid names the intent as the vertical spec and extracts horizontal docs on a second use.
## U127 The card shows what a name rule finds
The card rendered a banned-word rule as `(?!)`, so neither builder nor reviewer saw the words, and the merge gate refused a path holding one ([Naming rules](../design/naming.md)).
- AC-1 Each name rule on the card shows its `find`; one whose pattern is `(?!)` reads as "nothing may match" its `find`.
## U128 The card names its slice, its why and every reference
A card named sources with no path, did not say whether the unit was a vertical slice or horizontal work, and carried no business reason ([Unit card](../design/bolt-card.md)).
- AC-1 The card's `Spec:` line names the unit's slice and intent path, vertical with a top-level AC, horizontal without one or with no intent.
- AC-2 The card carries the unit's `# Why`, its interface lines as written with each link's path, and `## References` for each intent, unit, requirement or decision the text names, with its path.
## U129 A release ships a green base
`next` offered the owner's release on a base many merges ahead of its remote whose CI had failed every run ([CI on the base](../design/base-ci.md)).
- AC-1 With `ci.wait`, `next` asks for the push and the CI wait before the release prompt, waits on a red base, and `release` refuses a base not pushed or not green.
## U130 A fix round at work is waited for
With one focus's pass kept, `next` asked for another focus's review while the fix-round builder still committed ([In flight](../design/in-flight.md)).
- AC-1 A builder launched after the last verdict and the last report, its heartbeat fresh, makes the unit building whatever verdict a focus kept.
## U131 The Spec line names its evidence
A vertical or horizontal label that reads no evidence can contradict the card; it must be precise and deterministic ([Unit card](../design/bolt-card.md)).
- AC-1 The card's Spec line comes from the function `PLAN-SLICE` uses and names its evidence: the top-level ACs that prove a vertical unit, the vertical units that need a supporting one.
- AC-2 `PLAN-SLICE` reports a unit on a slice with a vertical unit that no vertical unit of the slice depends on.
## U132 Dependency tests stay offline
A unit test that checks each pin is the newest needs the network and turns every branch red on an upstream release ([Current dependencies](../design/dependencies.md)).
- AC-1 The card's Dependencies section says the live currency and advisory checks are `deps.check`, and a unit's test proves a check on fixed inputs offline.
## U133 A retried verdict counts once
Every record must be idempotent: a reviewer's retried `review record` appended a second round and could spend a fix round or escalate; a retried release reruns `deploy.run` ([Review rounds](../design/review-rounds.md), [Operations](../design/operations.md)).
- AC-1 The same verdict and findings for the same diff with no report in between replace their round.
- AC-2 Operations says `deploy.run` must be safe to run twice on one base.
## U134 Docs, diagrams and the pipeline aligned
With these units built, the docs, the diagrams and the tree are aligned and the noise cleaned ([Pipeline](../design/pipeline.md), [Increments and bolts](../design/increments-and-bolts.md)).
- AC-1 A pipeline page lists every stage in order; a slices page holds the plan rules, the Spec line and the slice release, and the oversized design docs fall under their caps.
- AC-2 The README, grid, overview and intent-state diagrams show slices, risks, the Spec line, reviews per focus and the CI wait before a release; M12 closes at U122 and M13 holds the rest.
## U135 Level paths name test files
With a folder such as `test/e2e/**` as a level's paths, a harness-only fix unit has no code to revert and no file a mutation can name ([Profile](../design/profile.md)).
- AC-1 The profile doc says `paths` name the test files, never a folder holding helpers, which are code the proof reverts.
## U136 Name neutral docs
The public repo names no vendor or product, only what it calls; a design doc heading named one.
- AC-1 No vendor or product name in the docs' prose, headings, source titles or examples; no vendor source URL either; a test fails on a listed name anywhere in them.
