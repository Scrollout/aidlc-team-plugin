# Goal
Every manual step the [M1 pilot](../pilot/report.md) needed ([Interventions](../pilot/interventions.md)) is gone or is an owner decision `next` names, the plugin runs on Windows, and `aidlc retro` shows per intent what fired and what to change.

# Why
The pilot merged 18 units but needed the owner or a hand step about 25 times. Each one is a rule the CLI or a hook can carry instead. The retro ([Steering](../design/steering.md#3-across-intents-the-retro)) measures whether that holds on the next project.

# Exit criteria
- `node --test` green on Linux, macOS and Windows; CI requires all three.
- A second pilot (an intent with at least two parallel units) runs with no hand edit to state and no lead step outside `next`; every remaining owner step is one `next` names.
- `aidlc retro` on that pilot's intent lists its codes, escalations and interventions and proposes at most three changes.
- CLI source within 3,000 lines (raised from 2,600 for M2, owner's choice).

# Out of scope (M3)
Proof-revert, security content patterns, `reserve` and `clean`, `check --staged`, org rule packs, Domain row templates for the full lane, Deployment and Operation rows, the CI evaluator agent, other agent hosts.

## U12 Windows
- AC-1 Every test passes on `windows-latest` with Node 22, 24 and 26, and CI requires it (57 failed at M1 exit).
- AC-2 Paths in messages, cards and runtime files use `/`, whatever the platform.
- AC-3 Hooks and the CLI run from a path with spaces and a drive letter.

## U13 Test and repo hygiene
- AC-1 Every test removes the temp dirs it makes, also on failure; a run leaves none behind.
- AC-2 `init` adds the builder worktree folder to the project's ignore files, so a project's tree-walking tests skip it.
- AC-3 `init` offers the project's lint target as a module check when one exists.
- AC-4 `push` on a base never pushed checks only commits after the one that added `.aidlc/profile.json`.

## U14 Board
- AC-1 An empty list from GitHub is suspect: `sync` compares it with the repo's issue count and retries with backoff before any create; a stub returning one empty page creates nothing.
- AC-2 `PLAN-BOARD` shows the profile's own value mapping in its example.

## U15 Steering and approvals
- AC-1 An approval held for the owner no longer hides independent work: `next` offers unit work whose docs do not wait on it.
- AC-2 The guard records each owner prompt it raised and whether it ran, so `next` and the lead can tell an answered prompt from a pending one.
- AC-3 Steer yields to a builder launched after a stopped report, and stops steering at a step `next` marks as parked for the owner.
- AC-4 Owner run-mode instructions (unattended, a stopping point, where to report) live in the local profile, are shown by `status`, survive a clear, and steer allows a stop at the stopping point.
- AC-5 `next` asks for every draft decision a unit cites, with the unit's re-approval.
- AC-6 A delegated `reapprove` refuses an edit that changes a unit's acceptance criteria ([0008](../decisions/0008-delegated-approvals.md), owner's choice).
- AC-7 `MODEL-MISMATCH` names the source of the expected model, and the card prints the reviewer model.

## U16 Builder start and upgrade
- AC-1 `start` on an existing unit branch merges the card's base into it first, so a restarted builder sees the work merged since.
- AC-2 `upgrade` copies from the installed plugin's release, and refuses a plugin tree with uncommitted changes.

## U17 Plan lint
- AC-1 A non-quick unit whose scope cannot hold a test in each AC level's paths is a finding naming the AC and the level.
- AC-2 A bare root-file scope that overlaps a `**` glob gets a finding that suggests the leading `/`.
- AC-3 An AC that names another unit's output (a check, a file or a target in that unit's scope) needs a dependency path to it.

## U18 Gate and guard
- AC-1 The card lists every level's `run`; the reviewer runs each in full, and the gate runs them on the merge result and records the pass in a `Tested` trailer, as AWS AI-DLC runs its verification command at every unit (research for the owner).
- AC-2 `next` checks the AC tags before it offers a merge; a quick unit's own AC tests must pass first.
- AC-3 Findings a re-approved spec change answers are marked answered on the card, and the re-review runs directly.
- AC-4 The guard allows a command that only redirects output or reads its exit code; writes to protected paths are still denied. The pilot's refusals came from the host's worktree isolation, which reads `.github` as git: builders run a check as one plain command.
- AC-5 `fix` on a full-lane path creates a unit that needs the owner's approval instead of refusing.

## U19 Docs and retro
- AC-1 The docs hook writes `generated.at` in UTC, so no stamp is in local time marked `Z`.
- AC-2 `aidlc check <dir>` below the bundle root resolves bundle-root links from the bundle root.
- AC-3 Regenerated indexes keep an existing description line for a new subfolder and keep the prose of an entry's hint.
- AC-4 Runtime counters in `.git/aidlc/stats.json`, one per finding code and escalation reason, bounded and reset by the retro.
- AC-5 `aidlc retro I-<n>` lists codes that fired 3 or more times, each escalation and each owner intervention, and proposes at most three changes: a profile glob, a project rule, a template tweak or a new check.

- AC-2 A step the host denied is not demanded again: steer allows the stop, and `next` names the owner's command once.

## U23 Researcher
[0010](../decisions/0010-research-and-advice.md), owner's choice.
- AC-1 A researcher agent with read and web tools only, on `models.research`, returns a digest with options, citations and open doubts; official sources first, secondary ones marked and never the sole support.
- AC-2 It starts only when the owner asks for research or the lead holds a question with a research reason; `next` names the step.

- The retro missed U-20's stop (its report was replaced by the restart's) and the owner's hand-run approvals.
- Also seen: cards show no checks when profile modules are keyed by `name`; requirement ids printed unpadded.
