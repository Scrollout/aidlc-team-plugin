# Goal
Reviews that end: a send-back names its reason, fix rounds are bounded, a re-review covers only what changed, and confirmed findings get fixed. Owner steps that stand out and come in fewer prompts, and a decision for every one-way door.

## U29 Card fixes
- AC-1 The card names each requirement as its file does (`R-057`).
- AC-2 Interface lines in the unit doc that are not links are kept on the card.
- AC-3 The proof note names the levels it will run, not every test glob.

## U30 Upgrade says where it stands
- AC-1 `upgrade` says when the CLI was already at that version and nothing changed.
- AC-2 It ends with the two commands that fetch a newer release and with the version it copied from, so an owner on an old install sees it.

## U31 Owner badges
The owner's suggestion, 2026-10-23: actions they must take stand out on a phone, by symbol as well as color.
- AC-1 A `next` line for an owner step starts with 👉, and one for a refusal or a stop with ⛔; the lead's own steps carry no badge. Each badge differs in shape, not only in color, and the badges are data in `cli.json`.
- AC-2 The skill has the lead show an owner step as its own block at the end of its message: the badge, numbered steps, and the words to type in a code block; it ends with ✅ when nothing is needed from the owner.

## U32 Send-back reason
From the [M4 pilot](../pilot/lessons.md).
- AC-1 When an AC has no tagged test on the unit's branch, the card lists it under `Findings to fix`, so a builder sent back sees why.
- AC-2 `review record` turns a `pass` into `fix` with one finding per AC that has no tagged test on the branch, and says so to the reviewer.
- AC-3 The retro lists each send-back of the intent's units.

## U33 Escalate after fix rounds
Owner's choice, 2026-10-23.
- AC-1 A review area escalates to the owner only when a `fix` would start fix round `review.fixRounds + 1` since the unit's last approval; the default is 3, and the profile can change it.
- AC-2 The message `review record` gives names the round count and the limit.

## U34 Re-review what changed
Owner's choice, 2026-10-23.
- AC-1 Each review round records the branch commit it reviewed.
- AC-2 After a fix round, a focus other than `general` keeps its last `pass` when the commits since it touch none of that focus's globs; `next` and the gate count it, and `general` always runs again.

## U35 Confirmed findings get fixed
Owner's choice, 2026-10-23.
- AC-1 A `pass` carrying a CONFIRMED finding is recorded as `fix`, and `review record` says why; PLAUSIBLE findings stay as notes on a pass.
- AC-2 The reviewer's prompt says a CONFIRMED finding blocks the merge.

## U36 Long calls keep agents alive
From the second M4 pilot: a reviewer running the card's test runs as one long Bash call looked dead after 2 minutes, and the steer hook asked for a second review. Owner's choice, 2026-10-23.
- AC-1 The heartbeat hook runs as each tool call starts as well as when it ends; it never blocks a call.
- AC-2 Only the end of a call marks an owner prompt as ran.
- AC-3 A mark stays fresh for 12 minutes, longer than the 10-minute Bash ceiling ([Agents in flight](../design/in-flight.md)).

## U37 Decision for a one-way door
The owner saw no decisions in the M3 and M4 pilots and asked for a check (2026-10-23). The owner chose the trigger: full-lane paths and interfaces, not focus globs.
- AC-1 Plan lint reports `PLAN-DECISION` for a live unit whose scope overlaps a `decisions.paths` glob (default: the profile's `lanes.full`) or an interface doc the unit links, when its body links no Decision doc and its frontmatter has no `twoWay: "<why it is easy to undo>"`. The message names the glob or doc and both fixes.
- AC-2 `approve` refuses a unit with `PLAN-DECISION`, with the same message, so the plan cannot be approved without the decision or the waiver.
- AC-3 `next`'s plan approval names the draft decision with the units, so the owner approves both in one prompt; a test holds it.

## U38 Reviewer escalation waits for the limit
From the [M4 pilot 2](../pilot/lessons.md); owner's choice, 2026-10-23.
- AC-1 `review record` records a reviewer's `escalate` as `fix` while the round is within `review.fixRounds`, and says so to the reviewer; past the limit it stays `escalate`.
- AC-2 The reviewer's prompt says an escalate is a fix round first: the builder fixes it or stops on its card's stop conditions.

## U39 Cited requirements in the first approval
From the [M4 pilot 2](../pilot/lessons.md).
- AC-1 `next`'s intent approval also names the draft requirements the intent cites, and the plan approval the draft requirements its units cite, so one owner prompt covers them.
