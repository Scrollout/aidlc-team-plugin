# Goal
A project started from scratch gets everything the owner expects from day one: bumps, an entry point to its docs, decisions beside its intent, lint at the gate, and diagrams that stay true; and one unit's question never stalls the others.

# Units
## U137 Init writes the Dependabot config
a Dependabot file added beside init's files was flagged `CI-COMMIT` on the first run, and every project wants bumps from day one ([Current dependencies](../design/dependencies.md)).
- AC-1 `init` writes `.github/dependabot.yml` for the workflow actions, among the files a direct commit may carry.
## U138 AGENTS.md names the root index
the AGENTS.md init writes said "read an index, then one doc" without naming the bundle's root `index.md`, the OKF entry point, so an agent had no first page ([Profile and templates](../design/profile.md)).
- AC-1 The AGENTS.md template's first docs pointer is `<bundle>/index.md`, read first, then the folder's index, then one doc.
## U139 Decisions take shape with the intent; no vendor left
a new project's intent sat in elaboration with no decision drafted, and the OKF design docs still named a vendor and its repository ([State](../design/state.md), [OKF](../design/okf.md)).
- AC-1 While a draft intent with open points links no decision, `next` asks the lead to draft the decisions it needs, linked from it, as the owner answers.
- AC-2 No vendor name or vendor URL in the docs, the name-neutral test covering them.
## U140 Project checks on every merge
CI's linter went red on the base, because the gate ran only the touched modules' checks and the test levels ([Profile and templates](../design/profile.md)).
- AC-1 The profile's `checks` run on every trial merge as `GATE-CHECK`, whatever the unit touches, and the card lists them.
## U141 A stop holds back no other unit
The prompt eval (2026-10-26): `next` kept naming one unit's stop, an owner question, ahead of another unit's review, so the back-fill never merged ([State](../design/state.md)).
- AC-1 A gated, escalated or stopped unit comes after the other units' review, fix round and restart.
## U142 Architecture you can see
The owner (2026-10-26): add and maintain logical and technical architecture diagrams and the codebase tree, with vertical slices and horizontal layers ([Codebase map](../design/codebase-map.md), [Plan lint](../design/plan-lint.md)).
- AC-1 A module's `layers` show in the tree, and a slices-and-layers page draws each slice across its layers with a matrix.
- AC-2 `PLAN-ARCHDOC` asks a unit that changes what the diagrams show to hold an architecture doc in its scope.
- AC-3 `init` writes an architecture doc template (logical and technical) and constitution rule 11.
## U143 A diagram updated first counts
The third project (2026-10-26): its slice-1 units all touch the deploy files; each holding the architecture docs in scope would make them overlap, while docs come before code anyway ([Plan lint](../design/plan-lint.md)).
- AC-1 `PLAN-ARCHDOC` also accepts a unit that links an architecture doc under `# Interfaces`, updated on the base before it builds.
## U144 No base commit during a merge
The second project (2026-10-26): a plan doc committed on the base while a 25-minute gate ran made the merge's fast-forward fail, and the whole gate was lost ([Verification](../design/verification.md)).
- AC-1 `aidlc merge` marks the base as merging while its gate runs and clears the mark after; the guard refuses a commit on the base while the mark is under two hours old.
## U145 A red base waits for its fix
The second project (2026-10-26): a fix unit refused for a red base was offered again after each plan commit, and the base's fix never built because its scope overlapped the refused unit ([CI on the base](../design/base-ci.md)).
- AC-1 A unit refused only with `GATE-BASE` stays refused until a merge lands, and no fix unit's build waits on its scope.
## U146 git -C ~/repo is that repository
The first migration (2026-10-26): `git -C ~/infra push origin main` was refused as a raw push of the project's base, because the guard read `~` literally ([Hooks](../design/hooks.md)).
- AC-1 The guard expands a leading `~` in a separate `-C` folder, as the shell does.
