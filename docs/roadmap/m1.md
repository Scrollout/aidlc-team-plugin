**TL;DR:** Nine units. U1 first; then U2/U3 in parallel; the rest follow the DAG. Done when a pilot intent with two parallel units runs from approval to merge on a a pilot project copy, inside the budgets.

## Goal
A project can `init`, approve an intent and plan, build units in parallel worktrees, and merge them through the gate, with every rule in the design enforced by the CLI or a hook.

## Why
Replace a heavier workflow tool with something smaller that cannot drift. Each later milestone builds on this loop.

## Exit criteria
- `node --test tests/` green; budgets test green.
- Pilot (U9): intent → 2 parallel units → both merged by `aidlc merge`, with no hand edits to state and no other workflow tool installed.
- Always-on context in the pilot ≤ 1,500 tokens, measured.
- Rendered project files contain no plugin name (test).

## Out of scope (later)
M2: `aidlc retro` and stats counters, proof-revert in the standard lane, org rule packs, Domain row templates for full lane. M3: Deployment/Operation rows, CI evaluator agent, other agent hosts.

### U1 Skeleton
Plugin manifest, marketplace entry pointing at `./plugin`, CLI entry with subcommand dispatch, exit codes, profile loader with layer merge, template engine.
- AC-1 `aidlc --help` lists the commands in [CLI](../design/cli.md); unknown command exits 64.
- AC-2 Profile layers merge in order; a `deny` from an earlier layer survives a later override.
- AC-3 Template renders `{{a.b}}` and `{{#each}}`; a missing variable is an error naming it; a project override file wins.
- AC-4 Budgets test fails when any budget in [Overview](../design/overview.md) is exceeded.
- AC-5 This repo's CI (GitHub Actions) runs `node --test tests/` and the docs check on every push.

### U2 OKF validator
Port a previous tool's validator per [OKF](../design/okf.md).
- AC-1 Each spec error code fires on its fixture and only there; a bundle with no indexes and a broken link is still spec-conformant.
- AC-2 House rules respect `profile.docs.rules`; a rule set to `error` exits 1.
- AC-3 Size caps follow the doc type.
- AC-4 This repo's `docs/` passes with `HOUSE-INDEX` as an error.
- AC-5 The spec's own examples (§4.3, §4.4, §10.2) pass as fixtures.

### U3 Grid and plan lint
Parse intent and unit docs; lint the plan; compute lanes.
- AC-1 Cycle in `depends` → `PLAN-DAG` naming the cycle.
- AC-2 Duplicate AC ID in a unit, or duplicate reservation across units → finding.
- AC-3 Two units with overlapping scopes and no dependency path between them → `PLAN-SCOPE`.
- AC-4 `lane` returns quick/standard/full per the profile globs, with the matching path as the reason.
- AC-5 An AC without a level, or with a level the profile does not define, is a finding.

### U4 State, next, approve, card
Per [State](../design/state.md) and [Unit card](../design/unit-card.md).
- AC-1 `status` derives every unit state from a fixture repo (docs, branches, trailers) with no state file.
- AC-2 `next` returns the documented action for each state in the order list.
- AC-3 `approve` writes the stamp; editing the doc makes it `stale`.
- AC-4 `card` renders from the base commit, refuses unapproved or stale units, stays ≤ 6,000 chars, and its hash changes when the unit doc changes.
- AC-5 The card's model follows the routing table for each lane, escalation signal and fix round.
- AC-6 Clear test: for each state (elaborating, plan pending, building with fresh and stale heartbeat, reported, reviewed, mid-merge), a fresh `next` returns the same action as before, starts no duplicate builder and loses no commit, report or verdict.

### U5 Init and templates
- AC-1 `init` on an empty repo and on a repo with an existing CLAUDE.md produces a valid profile, AGENTS.md ≤ 60 lines, a passing bundle and `.aidlc/bin/` with `VERSION`; it never overwrites without asking.
- AC-2 Rendered files contain no plugin name.
- AC-3 `upgrade` replaces `.aidlc/bin/` and nothing else.
- AC-4 `init --adopt` on a copy of an existing bundle keeps its layout, reports house-rule issues as warnings only, and lists other tools' leftovers without touching them.
- AC-5 With the plugin removed, `node .aidlc/bin/aidlc.mjs check --ci` still passes on the fixture.

### U6 Merge gate and CI mode
Per [Verification](../design/verification.md).
- AC-1 Each of the seven gate conditions fails on its fixture with its code and names its fix.
- AC-4 A diff matching a security glob or content pattern, outside the security folders, requires a security verdict.
- AC-5 Merge writes the index and log entries and regenerates `profile.shared` files; a builder diff touching them fails.
- AC-6 `push` refuses a base commit that is neither a gate merge nor docs-only; merge removes the unit's worktree and branch.
- AC-7 `fix` creates a one-unit plan with a regression-test AC; quick lane needs no approval, standard needs one.
- AC-8 A tagged test outside its level's paths fails the gate; in the full lane, an AC test that still passes with the production changes reverted fails the gate.
- AC-2 Passing gate merges `--no-ff` with `Unit`, `Card`, `Review` trailers.
- AC-3 `check --ci` flags a base merge commit lacking trailers or with files outside scope.

### U7 Hooks
- AC-1 guard denies each listed command and allows `git status`, `git commit -m`, `aidlc next`.
- AC-2 scope denies a write outside scope in a `unit/*` worktree and any edit to a `human:` `verified` entry or `verified_hash`; allows in-scope writes.
- AC-3 A hook whose CLI crashes denies (fail closed).
- AC-4 status injection ≤ 1,000 chars.
- AC-5 secrets denies a write containing a fixture key; allows the same file without it.
- AC-6 steer blocks a stop when `next` is autonomous, allows it at a human gate, and never blocks twice in a row.
- AC-7 The same denial three times in a turn returns `escalate`.
- AC-8 An Agent call starting a builder or reviewer with a model other than the card's is denied.

### U8 Skill and agents
- AC-1 Skill, builder and reviewer each ≤ 3 KB; descriptions ≤ 300 chars.
- AC-2 The skill tells the lead to act only on `aidlc next` output and lists no rule the CLI already enforces.
- AC-3 The reviewer prompt fixes the JSON contract; a test validates a sample against it.
- AC-4 The general reviewer prompt contains the security baseline; the security focus reads the threat model doc named in the profile.
- AC-5 `tests/evals/` seeded-defect fixture: the reviewer finds every seeded defect and the builder stops on the interface-change case (run manually; results in the pilot report).

### U9 Pilot
On a scratch copy of a real project, without any other workflow tool: `init`, one intent, two parallel units, merge both.
- AC-1 `docs/pilot/report.md` records tokens (always-on, per builder, per review), wall time, every hook denial and every manual intervention.
- AC-2 Each manual intervention becomes a fix unit or an M2 item.
- AC-3 The owner runs `/clear` twice during the pilot (once while builders run, once mid-elaboration); work continues with no repeated question and no lost work.
