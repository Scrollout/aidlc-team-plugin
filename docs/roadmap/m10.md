## U72 Design rows checked
- AC-1 Plan lint reports `PLAN-DESIGN` for an unapproved full-lane unit without content under `# Domain` or `# Logical`, and a standard-lane one without `# Logical`; `design: "<why none>"` waives it, quick-lane and approved units are not reported, and `aidlc fix` writes a waiver.
- AC-2 The unit template carries both sections; a card names the unit's design sections for the builder, and the reviewer prompt checks the diff against them.

## U73 Init follows the project's CI
A generated workflow with other pins than the project's own, and a red base with no path for a failure outside the repo, leave the lead guessing.
- AC-1 `init` writes `aidlc.yml` with the runner and the checkout and setup-node pins of the project's own workflows, the defaults otherwise.
- AC-2 A red base's `next` line names the rerun path for a failure outside the repo beside the fix unit; the `ARCH-BOUNDARY` fix and the architecture doc say a unit adding a boundary baselines the edges the base already has.

## U74 Silent skips, sync races and upgrades
- AC-1 An AC whose level has a `run` but no `paths` is `GATE-LEVEL` at merge, naming the level, instead of a proof skipped in silence.
- AC-2 `sync` that finds a Project item added between its read and its add (GitHub's auto-add of sub-issues) reads the items again with backoff and goes on; an item that stays unlisted stops it with the issue number.
- AC-3 The session-start status names an upgrade, with the installed plugin's command, when the pinned CLI is older; the skill and the pinned copy's refusal point to it.
- AC-4 `start` takes over a clean earlier worktree of the unit's branch even when the host still locks it.

## U75 Door scopes, security lines and proof
- AC-1 `PLAN-DECISION` names the scope glob that reaches the door and, for a bare name, suggests anchoring it.
- AC-2 An added line matching `security.content` requires the `security` focus review, in `next` and at the gate; a kept pass counts only when the fix adds no such line.
- AC-3 `check` warns `PROFILE-KEY` for a top-level or `security` key that nothing reads.
- AC-4 A unit that changes code and reports mutations is proved by them instead of by revert; they may edit its own diff.
- AC-5 The gate writes and stages the indexes, log and regenerated files on the merge result before any check runs.

## U76 Slice waiver bounded
Free text in `slice:` can waive end-to-end slices for any intent.
- AC-1 An unapproved unit of an intent with `slice:` whose scope reaches a module's paths or a one-way door is `PLAN-SLICE`, naming the glob; approved units are not judged again.

## U77 Card cap without findings
A fix round's card can go over the cap from its findings alone.
- AC-1 The card cap counts the card without its findings and mutations.

## U78 CI job summary
The run page is where CI is read.
- AC-1 With `GITHUB_STEP_SUMMARY` set, `check --ci` appends a job summary: the verdict, the findings with their fixes, each intent and unit with its state.

## U79 Release guard and report file
A tag push can publish a release with no owner prompt, and the host's worktree isolation refuses a builder's piped report.
- AC-1 The guard asks the owner for a push that can publish a tag: `--tags`, `--follow-tags`, `push.followTags`, a `refs/tags/` spec or an existing tag's name.
- AC-2 `report <unit> <file>` reads the JSON from a file, and the scope hook lets a builder write in the system temp folder outside every checkout; the card and the builder prompt say so.

## U80 Exception decisions on the base
A unit that carries its own baseline decision cannot have it approved before its merge.
- AC-1 A unit whose merged profile names an `except` decision that the base lacks gets `ARCH-BOUNDARY` naming the plan path: the lead commits it on the base for the owner, and the unit drops its copy.
- AC-2 `approve` finds a decision by its number (`0010` or `10`), as the owner types it.

## U81 Delegated upgrade
A migration upgrades the pinned CLI often, and an owner prompt for each one is noise ([0028](../decisions/0028-the-owner-can-delegate-upgrades.md)).
- AC-1 `aidlc delegate upgrade` lets the lead run the installed plugin's `upgrade` with no prompt; `--downgrade` and `--dirty` still ask; the session-start status says which applies.
- AC-2 An `ARCH-CHECK` from `check --ci` names the CI job's missing toolchain setup as the likely gap.
- AC-3 The guard knows the CLI by a Windows path too, so `approve` or `upgrade` through `C:\\…\\aidlc.mjs` still reaches the owner.

## U82 Board statuses
A unit under review shows Todo, and an intent with most units merged stays Todo.
- AC-1 `reviewing` and `gated` map to In review, `stopped` to On hold, and an approved intent with a unit past approval to In Progress.

## U83 Intents that ship nothing
An intent that changes only workflows is asked for a release, and tagging it would publish a product release.
- AC-1 With `modules` in the profile, an intent whose merges changed no file under a module or one-way door is released once merged, as a back-fill is; plan lint asks no runbook of one whose scopes reach none.
## U84 Board follows the plan
An intent and its approved units have no issues on the board while `sync` runs only after a merge.
- AC-1 `next` and `status` add `the board is behind: aidlc sync` when the issues `sync` would write differ from what it last wrote; never without `github`.
- AC-2 `sync` checks every planned value against the Project's options before any write and keeps the options; plan lint (`PLAN-BOARD`) flags a value they lack. (An unknown value would stop sync halfway.)
- AC-3 A unit waiting on a dependency (`blocked`) is Todo, not On hold.
## U85 Card hash without board fields
Changing a unit's track changes its card hash, and the merge gate refuses the review recorded on the old card (GATE-CARD).
- AC-1 The card hash leaves out the frontmatter the approval hash leaves out.
