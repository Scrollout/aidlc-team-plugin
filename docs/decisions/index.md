# Decision

* [0001 Derived state](0001-derived-state.md) - Progress is computed from git and the docs bundle; there is no ledger, event log or handoff file.
* [0002 Worktree subagents](0002-worktree-subagents.md) - Parallel workers are worktree-isolated subagents of one lead session, not peer sessions.
* [0003 Claude Code first](0003-claude-code-first.md) - Ship as a Claude Code plugin first; keep AGENTS.md and the CLI portable so other agent hosts can follow later.
* [0004 Vendored CLI](0004-vendored-cli.md) - The CLI is zero-dependency Node, copied into each project at .aidlc/bin and pinned there.
* [0005 One repo](0005-one-repo.md) - Develop and ship from one repo; the installable plugin is the plugin/ folder only.
* [0006 Engine behind adapters](0006-engine-behind-adapters.md) - Commands and hook rules are pure functions returning data; the CLI and hooks are adapters now, and MCP, HTTP hooks and A2A can be added later without changing the engine.
* [0007 Requirements and architecture as checks](0007-requirements-and-architecture-checks.md) - Lasting requirements become cited docs and architecture rules become gate checks, so a project cannot drift from its intended shape unit by unit.
* [0008 Delegated approvals](0008-delegated-approvals.md) - The owner can let the lead approve two classes of docs itself, re-approvals and quick-lane units, through an untracked personal setting; first approvals of intents, plans, requirements and one-way doors stay with the owner.
* [0009 Owner commands by permission prompt](0009-approval-prompt.md) - The owner runs owner commands (approve, upgrade, delegate, mode, release, rollback) by answering a yes/no permission prompt that the guard raises when the lead runs them, so they work from the mobile app and the web, where ! commands do not run.
* [0010 Research for open questions](0010-research-and-advice.md) - A question the owner cannot answer, or one with no clearly best option, goes to a researcher subagent on a cheap model that writes a cited digest from the project's own sources, official ones first; the lead drafts the decision and the owner still approves.
* [0011 Plain-word approval](0011-plain-word-approval.md) - The owner approves by typing exactly approve <doc>… as a prompt; a UserPromptSubmit hook stamps the docs before the lead sees the prompt, so approving needs no ! command, no path and no prompt the lead must raise.
* [0012 Typed go for release and rollback](0012-typed-go.md) - The owner releases or rolls back by typing exactly release I-<n> or rollback I-<n>; the prompt hook records a go for that command at the current commit, and the guard lets the lead's one matching call through and uses the go up, since a deploy outlasts the hook's time limit.
* [0013 A deterministic AI-DLC](0013-deterministic-ai-dlc.md) - One word per concept at each scale (core and extensions, domains of a fixed kind, slices and layers, intents, increments and bolts), every structural fact declared once and the rest generated, rules pinned per intent, and leftovers removed with their replacements.
* [0014 The reference cloud's API and event conventions](0014-cloud-api-and-event-conventions.md) - The naming registry ships, as the default grammar for every project's contracts and events, the control-plane API rules of the public cloud the owner chose as reference, and its system-event naming sent as CloudEvents 1.0.
* [0015 One-way doors are approved one at a time](0015-one-way-doors-approved-singly.md) - A typed approve may still name several docs, but never more than one one-way-door decision, and never a doc with an unresolved confirmed review finding; each one-way door is shown with its options, findings and facts before it is stamped.
