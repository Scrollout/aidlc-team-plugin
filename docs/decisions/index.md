# Decision

* [0001 Derived state](0001-derived-state.md) - Progress is computed from git and the docs bundle; there is no ledger, event log or handoff file.
* [0002 Worktree subagents](0002-worktree-subagents.md) - Parallel workers are worktree-isolated subagents of one lead session, not peer sessions.
* [0003 Claude Code first](0003-claude-code-first.md) - Ship as a Claude Code plugin first; keep AGENTS.md and the CLI portable so other agent hosts can follow later.
* [0004 Vendored CLI](0004-vendored-cli.md) - The CLI is zero-dependency Node, copied into each project at .aidlc/bin and pinned there.
* [0005 One repo](0005-one-repo.md) - Develop and ship from one repo; the installable plugin is the plugin/ folder only.
* [0006 Engine behind adapters](0006-engine-behind-adapters.md) - Commands and hook rules are pure functions returning data; the CLI and hooks are adapters now, and MCP, HTTP hooks and A2A can be added later without changing the engine.
* [0007 Requirements and architecture as checks](0007-requirements-and-architecture-as-checks.md) - Lasting requirements become cited docs and architecture rules become gate checks, so a project cannot drift from its intended shape unit by unit.
* [0008 Delegated approvals](0008-delegated-approvals.md) - The owner can let the lead approve two classes of docs itself, re-approvals and quick-lane units, through an untracked personal setting; first approvals of intents, plans, requirements and one-way doors stay with the owner.
* [0009 Owner commands by permission prompt](0009-owner-commands-by-permission-prompt.md) - The owner runs owner commands (approve, upgrade, delegate, mode, release, rollback) by answering a yes/no permission prompt that the guard raises when the lead runs them, so they work from the mobile app and the web, where ! commands do not run.
* [0010 Research for open questions](0010-research-for-open-questions.md) - A question the owner cannot answer, or one with no clearly best option, goes to a researcher subagent on a cheap model that writes a cited digest from the project's own sources, official ones first; the lead drafts the decision and the owner still approves.
* [0011 Plain-word approval](0011-plain-word-approval.md) - The owner approves by typing exactly approve <doc>… as a prompt; a UserPromptSubmit hook stamps the docs before the lead sees the prompt, so approving needs no ! command, no path and no prompt the lead must raise.
* [0012 Typed go for release and rollback](0012-typed-go-for-release-and-rollback.md) - The owner releases or rolls back by typing exactly release I-<n> or rollback I-<n>; the prompt hook records a go for that command at the current commit, and the guard lets the lead's one matching call through and uses the go up, since a deploy outlasts the hook's time limit.
* [0013 A deterministic AI-DLC](0013-a-deterministic-ai-dlc.md) - One word per concept at each scale (core and extensions, domains of a fixed kind, slices and layers, intents, increments and bolts), every structural fact declared once and the rest generated, rules pinned per intent, and leftovers removed with their replacements.
* [0014 The reference cloud's API and event conventions](0014-the-reference-clouds-api-and-event-conventions.md) - The naming registry ships, as the default grammar for every project's contracts and events, the control-plane API rules of the public cloud the owner chose as reference, and its system-event naming sent as CloudEvents 1.0.
* [0015 One-way doors are approved one at a time](0015-one-way-doors-are-approved-one-at-a.md) - A typed approve may still name several docs, but never more than one one-way-door decision, and never a doc with an unresolved confirmed review finding; each one-way door is shown with its options, findings and facts before it is stamped.
* [0016 The CLI budget is 5,000 lines](0016-the-cli-budget-is-5000-lines.md) - The CLI source budget rises from 4,000 to 5,000 lines for the v2 checks, because the incident rules turned out to be evidence for general rules, not patches to delete, and v2's own data already lives outside the code.
* [0017 The CLI is a library with extensions](0017-the-cli-is-a-library-with-extensions.md) - The CLI becomes a layered library (foundation kits, domains, a runtime) with opt-in extensions that plug in through named seams; the core never imports an extension, and the core and each extension have their own line budget.
* [0018 Standard formats over home-made ones](0018-standard-formats-over-home-made-ones.md) - Decisions follow MADR 4.0, acceptance criteria read as Given/When/Then, requirements are written in EARS, releases are logged per Keep a Changelog with SemVer, and architecture docs follow arc42 with C4 levels; the plugin checks each format the way it checks its own.
* [0019 The lead works in role personas](0019-the-lead-works-in-role-personas.md) - While it elaborates with the owner, the lead takes on a role persona (a product analyst for requests and requirements, an architect for domains and decisions) with that role's knowledge files; no extra agents and no simulated meetings, and every result is still checked by the CLI.
* [0020 Architecture models are data](0020-architecture-models-are-data.md) - A proven system is reverse-engineered from research into a vertical and horizontal architecture model, kept as data the CLI reads, shipped with the plugin or kept by a project, and applied to new and existing projects through the AI-DLC method; the plugin itself stays generic.
* [0021 The control plane's API conventions belong to its model](0021-the-control-planes-api-conventions-belong-to-its.md) - The resource-hierarchy part of decision 0014's grammar (scope segments, the providers segment and its namespace, the resource envelope's systemData, value and nextLink lists) moves from the plugin's defaults into the control-plane model's contract, applied only where a project chose that model; the generic casing and format rules stay the plugin's.
* [0022 One layout for shipped content](0022-one-layout-for-shipped-content.md) - Each content package the plugin ships (templates, personas, models, packs) sits at the top of the plugin folder and holds all it owns; a project pins one copy laid out the same way and overrides a file at the same path.
* [0023 Words follow the method and the reference architecture](0023-words-follow-the-method-and-the-reference.md) - The plugin's architecture words come from the method and the reference architecture - vertical slices that own their data and horizontal layers built once for every slice, with domains and extensions as the vertical kinds, an operation for one command or query, and internal layers inside a slice.
* [0024 Vertical slices are features, horizontal layers are technical concerns](0024-vertical-slices-are-features-horizontal-layers.md) - A vertical slice groups the code of one business feature or use case and cuts through every horizontal layer it needs; a horizontal layer groups code by one technical concern shared by every feature; a domain is the bounded context that holds a business capability's slices and its data.
